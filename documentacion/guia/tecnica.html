REFERENCIA DE IMPLEMENTACIÓN · 0.1.0

Cómo funciona
Visual BD.

Mapa de responsabilidades y funciones actuales. Rutas de módulos relativas a src/renderer/src/, salvo las que empiezan por main/ o shared/, relativas a src/. No es una API pública de servidor.

Documentación estática: no ejecuta IPC, no lee proyectos y no se conecta a proveedores. Los ejemplos del recorrido son ilustrativos.

01 / RESPONSABILIDADES

Tres procesos. Un modelo de dominio.

Renderer · React

Interfaz, store, dominio, operaciones, comparación y preparación de exportaciones.

src/renderer/src/
Preload · puente

Expone window.api mediante contextBridge. Invocaciones y suscripciones IPC.

src/preload/index.ts
Main · Electron

Ventana, menú, diálogos, disco, recuperación, credenciales y proveedores.

src/main/
UI → tienda → dominio → nuevo estado → render
           ↘ window.api → IPC → main → disco / proveedor
IA → comprobación → comparación → aprobación humana → historial

Electron, TypeScript, React 18 y Vite. La guía usa HTML, CSS y JavaScript sin dependencias nuevas.

02 / INVARIANTES

El diagrama representa el modelo.

domain/modelo.ts define Proyecto, Diseno, Entidad, Atributo, Clave, Relacion, Nota y ReglaNegocio. desconocido es explícito y distinto de falso, cero o una cardinalidad confirmada.

  • domain/operaciones.ts: catálogo cerrado de operaciones sobre diseño y reglas.
  • domain/historial.ts: edición, inversión de operaciones, deshacer y rehacer.
  • domain/propuestas.ts: afectados, huellas y conflictos. Un atributo necesita identidad de entidad y atributo; archivos anteriores se recuperan cuando esa relación es inequívoca.
  • domain/aprobacion.ts: aplicación atómica y decisiones. Revisar una aclaración sin operaciones no incrementa la versión del diseño.
  • domain/comparacion.ts: proyección local y diferencias compartidas entre lienzo e inspector.
  • domain/validacion.ts y normalizacion.ts: análisis con información declarada.

El lienzo mantiene cámara, zoom y arrastre transitorios. La estructura persistida procede del dominio, no del SVG dibujado.

06 / DECISIONES Y ESTADOS

Conectar no equivale a generar.

Sin configurar → Conectando → Conectado → Catálogo → Modelo elegido
Revisar → esperando → propuestas → comparar → aplicar / rechazar
                   ↘ error recuperable / respuesta descartada
Aclaración sin operaciones → discutir / marcar revisada

El coordinador elige Ollama o el adaptador OpenAI compatible. Solo local permite Ollama en loopback y bloquea proveedores remotos. Los perfiles se conservan por proveedor; seleccionar modelo lo establece como activo.

La revisión tiene un límite de 180 s por intento y hasta dos intentos ante un fallo de JSON. El transporte no repite automáticamente generaciones POST por errores HTTP; las consultas de catálogo tienen su política de recuperación. Reintentar explícitamente puede iniciar otra generación.

El renderer conserva la instantánea enviada y el turno/sesión para evitar resultados cruzados. Descartar no garantiza abortar en el servidor ni evita necesariamente sus cargos. Estados de propuesta: pendiente, aceptada, rechazada, desactualizada y aplicada; aceptada representa una aclaración revisada sin operaciones.

Las revisiones usan operaciones objeto con op, validador local cerrado y rechazo íntegro si el contrato falla. main/ia/contrato-revision.ts define el esquema. Ollama recibe esquema, contexto 8192 y temperatura 0,2; Gemini mantiene json_object y recibe el contrato en el mensaje de sistema. Esto aumenta contexto/tokens. El esquema no certifica la lógica.

domain/evaluacion-ia.ts comprueba referencias y advierte riesgos; los cambios sensibles requieren confirmación explícita y conservan la decisión. El proceso principal registra proveedor/modelo reales. Un 503 muestra saturación/indisponibilidad y no provoca una repetición automática del POST.

Las huellas no deben omitirse para forzar aprobaciones. Una recomendación plausible o un JSON válido no demuestran normalización correcta.

07 / INTERCAMBIO

Exportar una instantánea.

Se captura el modelo al abrir el diálogo, incluso con cambios sin guardar. exportadores/alcance.ts prepara completo, selección o propuesta; instantanea.ts construye la salida. Exportar una propuesta no la aplica.

FormatoUsoLímite
Markdown / JSON / paqueteLógica, inventario, reglas, pendientes y anexos opcionales.No genera SQL/ORM/NoSQL ni reemplaza .vbdproj.
SVG / PNGVector o imagen; fondo y escala PNG.No representa toda la semántica ni atributos propios de relaciones.
Mermaid ERDiagrama textual .mmd.No conserva todas las propiedades del dominio.
draw.ioTablas, atributos, conectores y notas editables.Reimportar no recupera sin pérdidas reglas, tipos, nulabilidad, claves y notas.

Seleccionar una relación incluye sus extremos. Las advertencias identifican selección parcial, propuesta y referencias por revisar. No se consulta IA. Consulta el contrato de exportación.

08 / EJECUCIÓN Y PRUEBAS

Desarrollo sin otra stack.

npm install
npm run dev

npm test
npm run typecheck
npm run build
npm start

Node 20+. Desarrollo probado en Windows. Los comandos pack y dist no equivalen a instaladores publicados ni compatibilidad certificada en todos los OS.

La regresión del 19 de octubre aprobó 176 pruebas deterministas. El comando npm run test:e2e compila y recorre Electron con perfil aislado y proveedor controlado. El ensayo de Ollama se omite por defecto: habilitar VISUAL_BD_QA_LOCAL=1 y ejecutar tests/integracion/ollama-real.test.ts realiza una llamada real al servidor local con el modelo instalado indicado en el ensayo y escribe evidencia en artefactos-locales/pruebas/<fecha-local>/, ignorada por Git. No es una prueba sin efectos externos.

La propia documentación mantiene sus 33 fichas en documentacion/guia/catalogo.js; guia.js comparte búsqueda, filtros y navegación entre las dos páginas. Actualiza ese inventario al añadir una función real.

La integración dominio/disco no sustituye un E2E completo de la interfaz. Procedimientos en las instrucciones.

09 / ALCANCE COMPROBADO

Lo disponible y lo pendiente.

Modelado relacional; no ejecuta migraciones ni se conecta a una base de producción. La imagen de referencia no se persiste en el proyecto. No hay comparación histórica de propuestas aplicadas.

Verificados: concurrencia IPC/UI, operaciones combinadas, accesibilidad básica en claro/oscuro, dos relanzamientos y referencia local de 500 entidades. La regresión Electron final aprobó quince grupos. Los recorridos reales Mistral y Flash Lite comprobaron revisión, decisión, guardado y reapertura; no certifican aprobación de cambios de negocio generados por IA. Pendientes: calidad semántica, aprobación real correcta por proveedor, cancelación efectiva, comparación histórica y evaluación manual con lectores. Herramientas externas y macOS/Linux siguen pospuestos. La disponibilidad y calidad de proveedores no se infieren de su catálogo.
